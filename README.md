# چه کسی وارد شده؟

یک آزمایش محلی با React، FastAPI و یک سرور واقعی Keycloak. بعد از ورود، نام کاربری و شناسهٔ خودت را در مرورگر می‌بینی. با یک کلیک، بک‌اند هم پاسخ مستقل خودش را نشان می‌دهد.

## اجرا روی مک

Docker Desktop را باز کن. در ترمینال بزن:

```bash
git clone https://github.com/ForuzanNaghdi/keyclock-test.git
cd keyclock-test
docker compose up --build
```

اولین بار ایمیج‌ها دانلود می‌شوند. صبر کن تا Keycloak در لاگ اعلام کند روی پورت 8080 گوش می‌دهد. سپس [صفحهٔ آزمایش](http://localhost:5173/) را باز کن. دقیقاً از localhost استفاده کن تا آدرس برگشت با تنظیمات یکسان باشد. سرویس‌ها فقط روی کامپیوتر خودت در دسترس‌اند.

## آزمایش پنج‌دقیقه‌ای

1. قبل از ورود روی «ارسال بدون توکن» بزن. FastAPI پاسخ 401 می‌دهد. یعنی برای این درخواست کاربری را تأیید نکرده.
2. روی «ورود به حساب» بزن. در صفحهٔ Keycloak گزینهٔ Register را بزن و یک حساب ساختگی بساز. فقط از اطلاعات و رمز آزمایشی استفاده کن. این حساب محلی است و به سامان وصل نیست.
3. بعد از برگشت، کارت «مرورگر من» را ببین. نام کاربری را از preferred_username و شناسهٔ پایدار کاربر را از sub می‌خوانیم. حتی اگر دو نفر هم‌نام باشند شناسه‌هایشان فرق دارد.
4. روی «ارسال با توکن» بزن. کارت دوم پاسخ واقعی GET /api/me را نشان می‌دهد. دو شناسه را مقایسه کن. در ترمینال دوم هم در پوشهٔ پروژه دستور زیر را بزن تا ببینی خود بک‌اند کدام کاربر را تأیید کرده:

   ```bash
   docker compose logs -f backend
   ```

5. همان‌طور که وارد هستی «ارسال بدون توکن» را بزن. نام تو در کارت اول دیده می‌شود ولی کارت دوم 401 می‌دهد. بک‌اند برای هر درخواست جداگانه مدرک می‌خواهد. برای مقایسهٔ دو نفر، خارج شو و با یک حساب آزمایشی دیگر وارد شو.

## وقتی روی ورود می‌زنم چه اتفاقی می‌افتد؟

| قدم | کجا؟ | چه اتفاقی می‌افتد؟ |
|---|---|---|
| باز کردن صفحه | frontend/src/main.tsx | پیش از نمایش React، برنامه می‌پرسد آیا از قبل نشست ورود داری. |
| شروع ورود | frontend/src/auth.ts | کتابخانهٔ keycloak-js مرورگر را با شناسهٔ برنامهٔ identity-web و آدرس برگشت به Keycloak می‌فرستد. |
| وارد کردن رمز | Keycloak در پورت 8080 | Keycloak آدرس برگشت مجاز را بررسی کرده، سپس کاربر را احراز هویت می‌کند. رمز در صفحهٔ Keycloak وارد می‌شود. |
| برگشت به فرانت | مرورگر | آداپتور کد یک‌بارمصرف را با PKCE به توکن تبدیل می‌کند. توکن در حافظه می‌ماند. کارت اول نام حساب را نشان می‌دهد. |
| کلیک روی ارسال با توکن | frontend/src/auth.ts | اگر توکن نزدیک انقضا باشد تازه می‌شود. سپس مرورگر توکن دسترسی را در هدر Authorization با پیشوند Bearer می‌فرستد. |
| پاسخ به درخواست | backend/main.py | API با کلید عمومی Keycloak امضای توکن را بررسی می‌کند. صادرکننده، مخاطب identity-api، نوع و زمان اعتبار هم کنترل می‌شوند. فقط بعد از تأیید، نام و sub را از توکن می‌خواند. |

## فایل‌ها را به چه ترتیبی بخوانم؟

- **keycloak/classroom.json** کلاس آزمایشی ما را تعریف می‌کند. realm یعنی فضای کاربران و برنامه‌ها. identity-web شناسهٔ عمومی فرانت است. آدرس برگشت و مبدأ مرورگر همین‌جا ثبت شده‌اند. تنظیم audience مشخص می‌کند توکن دسترسی برای کدام API است.
- **frontend/.env** سه آدرس و شناسهٔ عمومی راهنمای پیوست را با مقادیر محلی نگه می‌دارد. این مقادیر موقع بیلد وارد فرانت می‌شوند.
- **frontend/public/silent-check-sso.html** به آداپتور کمک می‌کند نشست قبلی مرورگر را بررسی کند. مرورگرهای دارای محدودیت کوکی ممکن است برای بررسی نشست، صفحه را جابه‌جا کنند.
- **frontend/src/auth.ts** تنها نمونهٔ Keycloak را می‌سازد. در این تمرین ورود را دستی شروع می‌کنی تا وضعیت قبل از ورود را ببینی.
- **frontend/src/main.tsx** دو کارت را نمایش می‌دهد. دکمهٔ دوم عمداً همان API را بدون توکن صدا می‌زند.
- **backend/main.py** پاسخ بک‌اند را تولید می‌کند. نام کاربر از بدنهٔ درخواست یا هدر نام کاربری دریافت نمی‌شود. sid شناسهٔ نشست است و ممکن است با ورود مجدد تغییر کند. برای شناسایی کاربر در این realm از sub استفاده می‌کنیم.
- **compose.yaml** سه سرویس را کنار هم اجرا می‌کند. nginx در فرانت درخواست /api را به FastAPI می‌فرستد. مرورگر و API از دید مرورگر یک مبدأ دارند. آدرس صادرکنندهٔ توکن همان localhost:8080 است که مرورگر می‌بیند. بک‌اند داخل Docker کلیدهای عمومی را با نام سرویس keycloak می‌گیرد.

## توقف و رفع اشکال

برای توقف در ترمینال اول Ctrl+C بزن، سپس `docker compose down`. حساب‌های محلی برای اجرای بعدی در volume می‌مانند. اگر صفحه هنگام شروع خطا داد، لاگ `docker compose logs keycloak` را ببین و بعد از آماده شدن سرویس روی «تلاش دوباره» بزن. دریافت 503 از API یعنی کلیدهای عمومی Keycloak در دسترس بک‌اند نیستند. برای دیدن پاسخ بدون توکن، مستقیم هم می‌توانی امتحان کنی:

```bash
curl -i http://localhost:8000/api/me
```

[راهنمای رسمی آداپتور جاوااسکریپت](https://www.keycloak.org/securing-apps/javascript-adapter)

## اتصال به Keycloak سازمان

در کنار compose.yaml یک فایل .env.local بساز و SSO_URL (آدرس پایه بدون اسلش آخر)، SSO_REALM و SSO_CLIENT را از راهنمای سازمان بگذار. SSO_API_AUDIENCE شناسهٔ مخاطب همین بک‌اند است و پیش‌فرض آن identity-api است. تیم هویت باید این مخاطب را برای access token فرانتِ مجاز تنظیم کند. ساختن حساب در آزمایش محلی، حساب سازمانی ایجاد نمی‌کند.

```bash
docker compose --env-file .env.local -f compose.yaml -f compose.sso.yaml up --build -d frontend backend
```

فرانت روی http://localhost:5173 باز می‌شود. برای این کلاینت عمومی، هر دو آدرس http://localhost:5173/ و http://localhost:5173/silent-check-sso.html باید در Valid Redirect URIs، مبدأ http://localhost:5173 در Web Origins و آدرس http://localhost:5173/ برای بازگشت پس از خروج مجاز باشند. ورود در سرور سازمان انجام می‌شود. مرورگر و کانتینر بک‌اند هر دو باید به آن سرور دسترسی داشته باشند. اطلاعات ورود را فقط در صفحهٔ رسمی سازمان وارد کن.
